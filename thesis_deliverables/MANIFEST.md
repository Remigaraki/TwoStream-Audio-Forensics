# Thesis deliverables manifest

**Regenerate this entire folder (18 files) with:**

    python scripts/build_results.py && python scripts/build_deliverables.py

`build_results.py` computes `results/tables/` and `results/figures/` from
`results/preds_*.csv`. `build_deliverables.py` curates and (for 3 files)
reformats a manuscript-facing subset of those into `thesis_deliverables/`.
No manual steps. Neither script ever touches `results/preds_*.csv`, and
`build_deliverables.py` never writes anywhere under `results/`.

Everything below is derived from the **corrected** tables on `main` (post
`fix/mcnemar-discrepancy`, merged at commit `354134b`).

## figures/

All 4 figures: 300 DPI, per-model marker + line style (see table below) kept
distinct without relying on colour, legend placed outside the axes so it
never occludes data.

| `degradation_curve_mindcf_log.png` | minDCF vs. condition, log scale, all 5 models, 7 conditions | Chapter 4 (figure number not given to me — could not be determined; please confirm) | `scripts/build_deliverables.py::build_mindcf_figure()`, reading `metrics_long.csv`, styled to match `degradation_curve_eer_log.png` |

Per-model marker / line style (`scripts/build_results.py::MODEL_MARKERS` / `MODEL_LINESTYLES`,
imported by `build_deliverables.py` so the minDCF figure stays consistent):

| Model | Marker | Line style |
|---|---|---|
| A0 | circle | solid |
| A1 | square | dashed |
| B0 | triangle-up | dash-dot |
| C1 | diamond | dotted |
| C2 | triangle-down | dense dash-dot-dot |

**Known limitation, checked and not fixable by styling:** at conditions
where two models' EER/minDCF are within a few hundredths of a percentage
point of each other (e.g. C1 vs C2 at Opus 32k: 1.32% vs 1.33%; at Opus 16k:
2.38% vs 2.47%), their markers sit almost exactly on top of each other
regardless of marker shape or size — verified by rendering to grayscale and
inspecting that region directly. This reflects those models' genuinely
near-identical performance at those specific conditions, not a rendering
defect; larger markers make the overlap worse, not better, and offsetting
the points to force visual separation would misrepresent the data. Where
the markers coincide, the two series stay distinguishable by tracing each
line's dash pattern away from the shared point. Elsewhere in the low-EER
band all 5 series are cleanly separable in grayscale.

## Reproducibility

Confirmed end-to-end on a clean checkout of the commit this file ships in:
`python scripts/build_results.py && python scripts/build_deliverables.py`
reproduces all 18 files in this folder byte-for-byte (`diff -r`, zero
differences). No file here depends on a manual step or an uncommitted script.
